 AWS VPC and Web Server Lab

 Objective

To configure and explore networking components within an Amazon Virtual Private Cloud (VPC) and launch a web server in the configured network environment.

The purpose of this exercise was to understand how AWS networking components work together to provide connectivity and controlled access to cloud resources.

 AWS Services

* Amazon VPC
* Amazon EC2
* Security Groups
* Route Tables
* Internet Gateway

 Lab Environment

* AWS Management Console
* Controlled AWS lab environment
* AWS Region: US East (N. Virginia)

 VPC Configuration

The lab involved working with a VPC and its associated networking components.

The following components were explored and configured:

* VPC
* Subnet
* Route table
* Internet Gateway
* Security Group

These components work together to provide network connectivity and control traffic to and from resources deployed within the VPC.

 Web Server Deployment

An EC2 instance was launched within the configured VPC environment.

The instance was configured as a web server and connectivity was tested to verify that the networking configuration was functioning correctly.

 Security Group Configuration

A security group was used to control inbound and outbound traffic to the EC2 instance.

The configuration demonstrated how security groups can be used as a virtual firewall to control network access to AWS resources.

 Key Learning

This exercise helped me understand the relationship between AWS networking components and how they work together to provide connectivity.

I gained practical experience with VPCs, subnets, route tables, Internet Gateways, and security groups while deploying an EC2-based web server.

The lab also reinforced the importance of controlling network access and only allowing the traffic required by a workload.

 Conclusion

The VPC lab provided practical experience with AWS networking and helped strengthen my understanding of how cloud resources communicate within a virtual network.

I also gained a better understanding of how security groups and routing configurations contribute to securing and connecting AWS workloads.
